Adoption

How hunt and arabesquelabs.com move onto the system, one change at a time, each change shippable on its own and checked in all four theme × direction combinations before the next. Nothing here has been done yet: the system was built without touching either repository.

Principles

  • Tokens first, then components, then interaction. Each phase leaves the site working and looking (almost) the same.
  • Alias, then rename, then remove. Old names point at new tokens for a release, so nothing breaks while call sites move.
  • One component per change, with its screenshots in four combinations attached to the review.
  • Vendored, pinned. Each site copies dist/ at a tagged version (see the README's versioning) rather than linking to a moving target.

hunt

hunt's CSS is plain (src/web/tokens.css, src/web/style.css, 1,322 lines), built into the binary. It already uses logical properties and supports Arabic.

Load the Arabic web fonts (IBM Plex Sans Arabic, Kufam, Amiri) at the same time, and replace [dir="rtl"] * { letter-spacing: 0 !important } with the system's :lang(ar) rules.

Phase 2: base and layout

  1. Replace hunt's reset and typography with css/base.css (via dist/arabesque.css, whose cascade layers sit under hunt's unlayered CSS, so hunt's rules still win while they exist).
  2. Map font sizes onto the nine-step scale and paddings onto the spacing scale, a file region at a time.
  3. Breakpoints: 720px and 640px → md (52rem) and sm (40rem); 900px → lg.

Phase 4: interaction

The audit's hop table (00-audit.md §6) is the plan, one task per change:

  1. Delete → Undo toast instead of the confirm dialog at its 17 call sites; keep confirmation for deleting an account and for replacing imports.
  2. "Move to…" menu on the board card and the application header.
  3. "Add a step" in view mode on the timeline.
  4. Settings that save on change, with a save state beside them.
  5. The offer toast's "Compare" link straight into the comparison.
  6. Save states, changed-field marks and stale markers on the take-home page.

arabesquelabs.com

A React site compiled with Tailwind v4 and shadcn naming; no Arabic yet.

Phase 1: tokens

Import dist/tokens.css and dist/tailwind-theme.css in the site's CSS entry, so Tailwind utilities resolve to the system's variables, then point shadcn's names at them:

Phase 2: focus and forced colours

Replace Tailwind ring utilities (box-shadow) with the system's outline focus; add the base layer's forced-colours and reduced-motion rules.

Phase 3: components and pattern

Swap the hero's pattern for js/pattern.js (same geometry, now drawn by rule), the header and footer for the lockup and .al-footer, and buttons for .al-button.

Phase 4: Arabic

Add /ar/ with lang="ar" dir="rtl", the Arabic fonts, and copy written in Arabic; the components need no changes for it.

Done when

  • No colour, size, space or radius in either site that isn't a token.
  • No left/right in either site's CSS outside chart value axes.
  • axe reports nothing, in four combinations, on every page.
  • The two sites share dist/, at the same version.
