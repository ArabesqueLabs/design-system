# JavaScript helpers

Generated by `scripts/build.mjs` from [`js/`](../js/): each helper as its
own source describes it, and its types. They're optional: plain ES modules
with no dependencies, one for each behaviour the CSS can't give. Import the
ones you need, from the same version as the CSS:

```html
<script type="module">
  import { initTabs } from "https://design.arabesquelabs.com/v/0.9.0/js/tabs.js";
  initTabs();
</script>
```

The React components (`dist/react/`) call them for you ([React](react.md)).

## announcement

Announcements: a [data-dismiss] button hides its .al-announcement and
remembers it (localStorage, by data-announcement), so it stays gone on
every page; focus moves on to what came after it. Where storage isn't
allowed, it's gone for this page only.

**Used by:** [Phase banner](components/phase-banner.md). **Source:** [`js/announcement.js`](../js/announcement.js).

```ts
/** Hide the announcements already dismissed, and wire each [data-dismiss] button inside root. */
export function initAnnouncements(root?: ParentNode): void;
/** Show an announcement again on the next load. */
export function forgetDismissal(id: string): void;
```

## chart

A chart's marks from the keyboard: one tab stop for the whole chart, and
the arrow keys move from mark to mark (along the reading direction, so
reversed in right-to-left); Home and End jump to the ends. Each mark is
role="img" with its value and what it is as its name, so focusing one
says it; the tooltip shows the same.

  <span class="al-chart__bar" data-series="1" role="img" aria-label="£120,900 Offer A, Year 1"
        data-al-tip="£120,900|Offer A, Year 1"></span>
  initChartKeys(chartElement);

**Used by:** [Charts](components/chart.md). **Source:** [`js/chart.js`](../js/chart.js).

```ts
/** One tab stop for a chart; the arrow keys, Home and End move between its marks. */

```

## copy

Copy buttons: a [data-copy] button copies the text of the element it
names (aria-controls), or else of its code block or command (the panel
that's showing, when there are tabs). Then it says so: its label reads
"Copied" for a moment, and the block's status region tells screen
readers. If the clipboard is refused, the text is selected instead, for
the person to copy themselves.

**Used by:** [Code and command](components/code.md). **Source:** [`js/copy.js`](../js/copy.js).


## count

Character count, the GOV.UK way: what's left, said in words, and how far
over once it's over; typing past the limit is allowed (a paste isn't
cut), and the message turns into an error. The visible message updates
at once; screen readers hear it after a pause, through a polite region.

  <div class="al-field">
    <label class="al-label" for="desc">Description</label>
    <textarea class="al-textarea" id="desc" data-al-maxlength="200"></textarea>
  </div>
  initCharacterCounts(document, {
    words: (left) => left >= 0 ? `You have ${left} characters remaining` : `You have ${-left} characters too many`,
    limit: (max) => `You can enter up to ${max} characters`,
  });

Over the limit, the field is marked aria-invalid="true"; the mark is
removed again only if this helper set it, so validate.js's stays.

**Used by:** [Character count](components/character-count.md). **Source:** [`js/count.js`](../js/count.js).

```ts
export interface CountOptions {
  /** The message for what's left (left ≥ 0) or how far over (left < 0). */
  words?: (left: number) => string;
  /** The static description of the limit, read with the field. */
  limit?: (max: number) => string;
}
/** Character counts for every [data-al-maxlength] under root; returns a function that redraws them. */
export function initCharacterCounts(root?: ParentNode, options?: CountOptions): () => void;
```

## datepicker

Date picker: a text field for a date near today, with a calendar to
choose it from (the WAI-ARIA APG date picker dialog). Unlike the
browser's <input type="date">, it speaks the page's language: month and
day names, the order of the week, the digits people chose (Western or
Arabic-Indic) and, in right to left, a grid that runs from the right.
The date can always be typed instead, in either digit set; it's kept as
an ISO date (2026-11-30) in a hidden field that takes the input's name.
Gregorian only.

  <div class="al-field">
    <label class="al-label" for="due">Due date</label>
    <span class="al-hint" id="due-hint">For example, <span data-al-date-example="2026-11-30">30/11/2026</span></span>
    <div class="al-date-picker">
      <input class="al-input" id="due" name="due" value="2026-11-30" aria-describedby="due-hint" data-al-date-picker>
      <button type="button" class="al-button al-button--icon al-date-picker__toggle" aria-label="Choose date">
        <svg class="al-icon" aria-hidden="true"><use href="/dist/icons.svg#al-icon-calendar"></use></svg></button>
    </div>
  </div>
  const [due] = initDatePickers(document, { numerals: () => chosenDigits });
  due.value; // "2026-11-30"

In the calendar: arrow keys move by day and week (along the reading
direction), Home and End to the week's ends, Page Up and Page Down by
month (with Shift, by year), Enter or Space chooses, Escape closes;
focus goes back to the button. data-min and data-max (ISO) on the input
limit what can be chosen.

**Used by:** [Date picker](components/date-picker.md). **Source:** [`js/datepicker.js`](../js/datepicker.js).

```ts
import type { Numerals } from "./format.js";

/** A date-only value: "YYYY-MM-DD". */
export type IsoDate = string;
type Live<T> = T | (() => T);

export interface DatePickerLabels {
  /** The previous-month button's name; default "Previous month". */
  previous?: string;
  /** The next-month button's name; default "Next month". */
  next?: string;
}
export interface DatePickerOptions {
  /** Labels in the page's language; a function is read each time it draws. */
  labels?: Live<DatePickerLabels>;
  /** Western ("latn", the default) or Arabic-Indic ("arab") digits. */
  numerals?: Live<Numerals>;
  /** The language; by default the input's nearest lang. */
  lang?: Live<string>;
}
export interface DatePicker {
  readonly input: HTMLInputElement;
  /** The chosen date, or null if none (or what's typed isn't a date). */
  value: IsoDate | null;
  open(): void;
  close(): void;
  /** Draw again in the current language and digits. */
  refresh(): void;
  /** Take the picker away; the input keeps its value and name. */
  destroy(): void;
}

/** Every input[data-al-date-picker] under root becomes a date picker. */
export function initDatePickers(root?: ParentNode, options?: DatePickerOptions): DatePicker[];
/** A typed date, day first, in either digit set; null if it isn't a date that exists. */
export function parseDate(text: string): IsoDate | null;
/** A date as it's written in the language and digits: "30/11/2026", "٣٠‏/١١‏/٢٠٢٦". */
export function formatDate(iso: IsoDate, options?: { lang?: string; numerals?: Numerals }): string;
/** The week's first day where the language is used, as JS counts days (0 Sunday … 6 Saturday). */
export function weekStart(lang?: string): number;
/** A month (0–11) as weeks of 7 dates, null outside the month. */
export function monthGrid(year: number, month: number, weekStart?: number): (IsoDate | null)[][];
/** Where a key moves the focused date; null if it doesn't. */
export function step(iso: IsoDate, key: string, options?: { rtl?: boolean; shift?: boolean; start?: number }): IsoDate | null;
/** Today, where the person is. */
export function today(): IsoDate;
```

## dialog

Dialogs that don't lose work (from Apple's HIG): if closing would throw
away what someone typed, the dialog doesn't close; a bar inside it asks
to keep editing or discard. Never a second dialog on top.

  <dialog class="al-dialog" id="edit">
    <form method="dialog"> …fields…
      <div class="al-dialog__discard" hidden role="alert">
        <p>Discard your changes?</p>
        <button type="button" class="al-button al-button--sm" data-al-keep>Keep editing</button>
        <button type="button" class="al-button al-button--sm al-button--danger" data-al-discard>Discard changes</button>
      </div>
      <div class="al-dialog__actions"><button class="al-button" value="cancel">Cancel</button> …

  import { openDialog } from "./js/dialog.js";
  openDialog(document.getElementById("edit"));

Escape is caught on keydown, before the browser's own close: browsers
let a page refuse only the first close request, so a second Escape would
otherwise close a dialog with unsaved work. If a close gets past anyway,
the dialog reopens with what was typed, and asks.

**Used by:** [Dialog](components/dialog.md). **Source:** [`js/dialog.js`](../js/dialog.js).

```ts
/** Open a modal dialog that won't close over unsaved changes; focus returns to the opener. */
export function openDialog(dialog: HTMLDialogElement, options?: { opener?: Element | null }): void;
```

## format

Numbers, money and percentages in the page's language, with the digits
people chose. Arabic can be written with Western digits (123, the
default, as on most Arabic sites and in finance) or Arabic-Indic (١٢٣);
it's a preference, kept with the person's other settings, never inferred.

  formatNumber(108000, { lang: "ar", numerals: "arab" })  → "١٠٨٬٠٠٠"
  formatMoney(6010, "GBP", { lang: "ar" })                → "£6,010"
  formatMoney(6010, "GBP", { lang: "ar", numerals: "arab" }) → "£٦٬٠١٠"

Put the result in <bdi> (or .al-ltr) inside running text, so it stays
whole in right-to-left; where it goes into a string (an aria-label, a
tooltip), wrap it in U+2066 … U+2069. With Arabic-Indic digits this
matters more: they don't carry "£" with them as Western digits do.

**Used by:** [Field](components/field.md). **Source:** [`js/format.js`](../js/format.js).

```ts
export type Numerals = "latn" | "arab";
export interface NumberOptions extends Intl.NumberFormatOptions { lang?: string; numerals?: Numerals }
export interface MoneyOptions extends NumberOptions { signDisplay?: "auto" | "always" | "exceptZero" | "never" }
/** The Intl locale for a language ("en", "ar", "ar-SA"…) and a numeral system. */
export function numberLocale(lang?: string, numerals?: Numerals): string;
export function formatNumber(value: number, options?: NumberOptions): string;
/** The short symbol for a currency (£, $, €), or its code where there's none. */
export function currencySymbol(currency: string): string;
/** The symbol first, in both languages: "£6,010", "£٦٬٠١٠", "SAR 100". */
export function formatMoney(value: number, currency?: string, options?: MoneyOptions): string;
export function formatPercent(fraction: number, options?: NumberOptions): string;
/** Typed numbers in either digit set, and this module's own output; NaN if it isn't one. */
```

## keys

Keyboard shortcuts that follow the platform (from Apple's HIG): ⌘ on
Apple devices, Ctrl elsewhere, and the standard meanings kept (⌘Z
undo, ⌘S save, ⌘K or / search, Escape to dismiss). Single-key
shortcuts never fire while typing in a field, and can be turned off
(WCAG 2.1.4): offer setShortcutsEnabled() as a setting.

  <kbd class="al-kbd" data-al-mod></kbd> <kbd class="al-kbd">K</kbd>
  renderModifierKeys();                      // fills [data-al-mod] with ⌘ or Ctrl
  onShortcut("mod+k", () => search.focus());
  onShortcut("mod+shift+z", redo);           // Shift is matched exactly…
  onShortcut("?", () => shortcuts.showModal()); // …except for symbols typed with it

On a non-Latin layout (Arabic, say) the key is matched by its position,
so ⌘K and / still work.

**Used by:** [Keyboard keys and shortcuts](components/kbd.md). **Source:** [`js/keys.js`](../js/keys.js).

```ts

/** "⌘" on Apple devices, "Ctrl" elsewhere. */

export function renderModifierKeys(root?: ParentNode, options?: { titles?: { apple: string; other: string } }): void;
/** Whether single-key shortcuts are on. */
export function shortcutsEnabled(): boolean;
/** Turn single-key shortcuts on or off (WCAG 2.1.4); remembered. */
```

## pattern

The tessellation: Hankin's "polygons in contact" on the 4.8.8 tiling
(regular octagons and squares). From each edge's midpoint two strands
leave at the contact angle θ (67.5° by default); the strands leaning
towards a vertex meet on its bisector, at (side/2)·sin θ / sin(θ + α/2)
from it, α being the polygon's interior angle. One repeat is side·(1+√2)
square, centred on a square, with a quarter octagon in each corner; the
mark is the same tile centred on an octagon.

## theme

Theme: follow the system's light or dark, unless the person chose one;
the choice is remembered, and kept only while it differs from the system
(when they agree again, the override goes).

So there's no flash, apply the stored choice with a classic inline
script in the <head> (a module is deferred, so it runs after first paint):
  <script>try { const t = localStorage.getItem("al-theme"); if (t === "light" || t === "dark") document.documentElement.dataset.theme = t; } catch {}</script>
then import this module for the toggle. It's safe to import where there's
no window (server rendering): nothing runs until a function is called.

**Used by:** [Site header](components/site-header.md). **Source:** [`js/theme.js`](../js/theme.js).

## toast

belong in the page (a notice by the field), not only here.

  toast("Process archived", { action: "Undo", onAction: () => restore(), dismissLabel: "Dismiss" });

## validate

Validation, the GOV.UK way: check on submit (not while people type), and
when something's wrong, show an error summary at the top of the form,
listing each error as a link to its field, focus it, and put "Error: " at
the start of the page title. Beside each field, the same message, with a
hidden "Error:" for screen readers. Shown even for one error.

  import { validateOnSubmit } from "./js/validate.js";
  validateOnSubmit(form, [
    { field: "#name", check: (v) => v.trim() ? "" : "Enter the project name" },
    { field: "#email", check: (v) => /.+@.+\..+/.test(v) ? "" : "Enter an email address in the correct format, like name@example.com" },
  ], { onValid: (form) => save(form) });

Give the form `novalidate`, so the browser's own bubbles don't compete.

**Used by:** [Character count](components/character-count.md), [Date picker](components/date-picker.md), [Error summary](components/error-summary.md). **Source:** [`js/validate.js`](../js/validate.js).

```ts
export interface Check {
  /** A selector inside the form, or the field itself. */
  field: string | HTMLInputElement | HTMLSelectElement | HTMLTextAreaElement;
  /** The error message, or "" when the value is fine. */
  check: (value: string, input: HTMLInputElement | HTMLSelectElement | HTMLTextAreaElement) => string;
}
type Text = string | (() => string);
export interface ValidateOptions { onValid?: (form: HTMLFormElement) => void; title?: Text; prefix?: Text; sprite?: string }
/** Check on submit, with an error summary and inline errors. Throws at once if a field isn't there. */
export function validateOnSubmit(form: HTMLFormElement, checks: Check[], options?: ValidateOptions): { clear: () => void };
```
